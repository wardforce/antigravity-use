# AGY 编排方案

## 编排结论

不把三个写入任务同时交给 AGY。它们构成明确的依赖链：配置契约先确定，后端才能按该契约读取并形成稳定返回，前端再依据后端返回契约适配。强行并行会让后端和前端基于未定稿接口猜测，同时存在共享配置文件被覆盖的风险。因此仅并行执行只读侦察，实际修改按“配置 → 后端 → 前端”串行，并在每一步之间设置主模型验收门。

当前预检已尝试运行 `agy models`，但 CLI 报告未登录，没有取得实时模型清单。正式执行时先恢复登录并重新运行 `agy models`；只从实时返回的 slug 中选择足以完成任务的最低成本模型，不用静态名称冒充当前可用模型。

## 0. 主模型建立基线

在任何 AGY 写入前，由主模型完成：

1. 读取仓库级指令和相关模块文档。
2. 运行 `git status --short`，记录用户已有的已跟踪与未跟踪改动；禁止 reset、checkout、stash 或覆盖它们。
3. 定位唯一的配置文件、读取配置的后端模块、后端响应类型/接口，以及消费该响应的前端组件和相关测试。
4. 记录三类契约基线：配置键、类型和默认值；后端响应字段、类型和缺省语义；前端现有 loading/error/empty 状态。
5. 确定可执行的最小验证命令。若无法唯一确认目标文件，先停在只读侦察，不让 AGY猜测并写入。

只读侦察可并行分成三路：配置与引用关系、后端调用链与测试、前端消费链与测试。每路使用 `--mode plan`，且明确禁止修改文件。主模型汇总结果后，锁定下述三个步骤的文件白名单。

## 1. AGY 修改配置契约

- 依赖：仅依赖基线完成。
- 文件范围：只允许修改已确认的一个配置文件及其直接配置测试；不允许触碰后端模块和前端文件。
- 提示内容：写清新增/变更的配置键、类型、默认值、兼容要求，以及必须保留的用户现有改动；要求返回检查文件、修改文件、验证命令与结果、遗留问题、越界情况。
- 验收条件：配置可解析；字段名称和类型唯一确定；默认值/缺省行为有测试或静态校验；diff 仅落在白名单；用户已有改动保持原样。
- 主模型验收：亲自检查工作区 diff，并运行配置层验证。AGY 返回退出码 0 或 `SUCCESS` 只视为传输成功，不视为任务验收通过。

验收通过后，把最终配置契约摘要作为步骤 2 的固定输入，之后不再允许步骤 2 擅自修改配置文件。

## 2. AGY 适配后端模块

- 依赖：步骤 1 已通过主模型验收。
- 文件范围：只允许修改读取该配置的后端模块、必要的后端类型/接口文件和聚焦测试；配置文件改为只读，前端目录禁止写入。
- 提示内容：附上已验收的配置键、类型和缺省语义，明确期望的后端返回契约及兼容边界。
- 验收条件：后端正确读取新配置；缺失、非法和默认场景行为明确；返回字段、类型和错误语义稳定；聚焦单元/接口测试通过；diff 未触碰配置和前端白名单外文件。
- 主模型验收：检查真实 diff 和测试输出，并将最终后端响应示例、类型、空值及错误语义冻结为步骤 3 的输入。

## 3. AGY 更新前端组件

- 依赖：步骤 2 已通过主模型验收，后端返回契约已冻结。
- 文件范围：只允许修改指定前端组件、直接相关类型和聚焦组件测试；配置文件与后端目录均为只读。
- 提示内容：提供后端响应示例和类型定义，要求覆盖成功、加载、空值和错误状态，不得自行发明后端字段。
- 验收条件：组件消费字段与已验收后端契约一致；类型检查、组件测试和相关构建通过；现有交互无回归；diff 仅包含允许文件。
- 主模型验收：检查 diff、测试/构建输出，并在可能时运行一条覆盖“配置 → 后端返回 → 前端渲染”的集成或端到端验证。

## AGY 调用与会话管理

正式执行每一步都在仓库根目录使用 headless 调用，形态如下：

```powershell
agy --model <从实时清单选择的slug> --mode accept-edits --output-format json --print '<含目标、白名单、依赖契约、验收命令和返回格式的提示>'
```

每一步保存 JSON 中的 `conversation_id`。若主模型验收失败，使用同一会话定向返工：

```powershell
agy --conversation <conversation_id> --mode accept-edits --output-format json --print '<具体差异、允许文件及未改变的验收条件>'
```

同一缺陷最多返工两轮。每轮后仍由主模型重新检查 diff 和验证结果；两轮仍不合格、AGY 扩大范围、会话丢失或持续报错时，停止该委派，由主模型接管最小必要修改。不会通过启动三个并行写会话来规避返工。

## 最终整体验收

三个步骤分别通过后，主模型再统一执行：

1. 对比最终 `git diff` 与基线，确认只出现计划内改动，用户原有修改未受损。
2. 校验配置键、后端读取逻辑、响应字段和前端消费字段四者一致。
3. 运行配置测试、后端测试、前端类型检查/组件测试，以及可用的集成或端到端验证。
4. 检查不存在并行会话遗留的冲突标记、重复字段、临时文件或未经说明的格式化噪音。
5. 仅在上述证据全部通过后报告完成；AGY 的自述不替代主模型验收。

本评测只产出这份编排方案，不执行上述写入任务，也不修改项目业务文件。
